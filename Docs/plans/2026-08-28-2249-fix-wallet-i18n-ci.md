# Fix wallet transaction i18n CI

Status: Complete

## Context

PR #23 fails the `verify:i18n` CI step because the customer wallet transaction history passes a `defaultValue` to `t()`. The repository intentionally forbids translation fallbacks in application code so every supported locale remains complete.

The existing `customer` locale resources already define the visible wallet transaction labels in English, Simplified Chinese, and Malay. No new translation model or duplicate keys are required.

## Decisions

- Reuse `ui.wallet.transactionType.*` from the existing `customer` locale resources.
- Remove the English `transactionLabel()` fallback from the customer transaction history.
- Add a contract assertion preventing `defaultValue` from returning to this component.
- Keep wallet transaction filtering, amount signs, theme colours, ledger data, and date localization unchanged.

## Scope

Files to modify:

- `components/customer/wallet/customer-transaction-history.tsx`
  - Remove the `transactionLabel` import.
  - Render the existing locale key without `defaultValue`.
- `components/customer/wallet/__tests__/customer-transaction-history.contract.test.ts`
  - Assert that the component does not use a translation `defaultValue`.
- `Docs/plans/2026-08-28-2249-fix-wallet-i18n-ci.md`
  - Record this plan and verification evidence.

Files explicitly not being changed:

- `app/i18n/locales/*/customer.json` because the required visible transaction keys already exist.
- `lib/wallet/transaction-display.ts` because vendor display and non-customer fallbacks are outside this CI failure.
- Wallet APIs, ledger logic, database migrations, and theme tokens.

New dependencies: none.

Database changes: none.

## Risks

- `WalletTransaction.type` is currently a string. A newly introduced transaction type must add translations to all customer locale files or the UI may display its key. CI should remain the enforcement point for that future change.
